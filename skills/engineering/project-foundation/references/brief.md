# Brief

One page. A reader who opens only this file should know who it is for, what the first version does, and what it refuses to do.

```markdown
# Brief: {Product name}

## Problem

{What is late, missing, or untrustworthy today.} [{tag}]

## User

{The person who feels that problem, and the moment it shows up.} [{tag}]

## Promise

{The outcome they can count on after the MVP exists.} [{tag}]

## MVP

{The smallest product that keeps the promise. Name the capabilities, not a phase slogan.} [{tag}]

## Non-goals

{The nearby product a builder will be tempted to add. One line each.}
```

The brief must agree with the PRD. If a capability is in the brief's MVP, some `FR-` has status `in`. If it is a non-goal, it is `later`, `cut`, or listed under scope `### Out`.
